# M2.8: depth-compare candidate and hardware checks

For Paper Mario 3D triangles, `gfx_tri_rebuild_state` enables comparison only when both `G_ZBUFFER` and `Z_CMP` are set. Other-mode writes already invalidate the cached triangle state. The backend's depth-mask state is still derived from `Z_UPD`, but this does **not** provide independent writes: scalar and NEON paths currently write only when depth testing is enabled. Thus for `G_ZBUFFER=1, Z_CMP=0, Z_UPD=1`, this fix changes the old behavior from compare-and-conditionally-write to neither compare nor write. A true no-compare depth write is not implemented; this is a material regression risk, not full N64 depth semantics. The targeted radial-shimmer material has both `Z_CMP=0` and `Z_UPD=0`.

No real-renderer pixel or ARM hardware test has yet run. The host regression exercises the exact extracted depth helper and other-mode invalidation code, and checks the existing backend limitation. Separate M28 identity: `PM64_DEPTH_FIX_M28=1`, app `PaperMarioPALAlpha045DepthFixM28`, build `PAL-0.4.5-DEPTH-FIX-M28`, trace prefix `m28`.
