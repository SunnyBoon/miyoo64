# Merlee ImgFX experimental test

Based on M2.6 commit 2544c8279e8984670e78ec62d07ed415108df28d and PMRET pin ee321921df2debdaae4c9c00426b6ea84f26adb5. The pinned source already passes an uninitialized ImgFXTexture to the shuffle and first two flip effects. A zero alpha makes imgfx_appendGfx_component return before advancing the effect. This is a real source defect, but its causal role on hardware is unproven.

The test candidate initializes the structure from dro_02_card and its palette. The existing card setup loads a 32 by 32 tile; these three animation headers use absolute coordinates. Their calls skip texture setup, so raster, palette, dimensions and offsets do not control the animation mesh in those paths. The existing fourth card effect uses alpha 255; the candidate uses the same fully opaque value. The fourth call retains its original sprite-derived setup. No ritual state transition is forced.

During TIMELINE only, the most recent 64 Merlee observations are buffered and written to trace.log on completion as MERLEE lines. `variant=fix` means the reported alpha and dimensions are initialized candidate values, never measurements of the original undefined object. `phase=2` is shuffle, `phase=31` and `32` are the first two flip effects, and `phase=3` records the actual transition to ritual state 3; texture fields of the transition row are -1 because no texture is sampled there. `dropped` counts overwritten rows. All records concern card index 0. A capture without a row does not prove that the card worker ran. No file access occurs in the card path.

The unchanged original's uninitialized value cannot be safely sampled by adding a C read: it is undefined, and instrumentation or a different compiler can change its behavior. Compare the separate M2.6 evidence and the candidate's observable progression, without claiming the original alpha was measured. A hardware test is necessary to establish whether this candidate fixes the softlock and preserves visuals.
